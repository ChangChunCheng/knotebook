# Folders

Nesting, sorting and dragging folders in the sidebar, and moving many notes at once. Part of [Known limitations](../known-limitations.md).

- **Folders nest up to five levels, but giving a deleted group's notes to an admin, or restoring notes from the trash, can make a deeper tree.** Renaming and deleting folders in such a tree still work; no folder can be added below the fifth level.
- **Undoing a folder deletion, or restoring its notes from the trash, re-creates only the folders on the way to a note you restore.** A folder with no notes in it or below it doesn't come back.
- **How the notes in a folder are sorted is remembered only in this browser,** not in your account; other browsers and devices show the default, **Last modified**.
- **Sorting by Size uses the size of a note's editing state plus its attachments,** so a short note that has been edited a lot can sort above a longer one.
- **Changes someone else makes to a group's folders show up when you come back to the window or reload the page,** not right away.
- **Moving many notes and folders at once within a space stops after about 600 in a minute — sooner if you've made other changes to folders in that minute.** Each note or folder moved within its space — with **Move to…** in a note's `⋮` menu or **Move to** in the sidebar's selection mode — and each one moved back with their **Undo** counts against a per-person limit of 600 changes to folders a minute, which creating, renaming and deleting folders also count against, in the web app or with MCP's `create_folder`, `rename_folder`, `move_folder`, `move_note_to_folder` and `delete_folder`; deleting a folder counts as one, however many notes it moves to the trash. It is separate from the limit of 30 writes a minute that copying and AI edits use (see "Copying many notes at once from the sidebar…" in [Limits](./limits.md)): moving notes doesn't use that one up. A larger selection stops partway with "Too many requests. Please slow down.", and so can its **Undo** right after the move; the message says how many items were moved, or moved back, and after a stopped move the item it stopped at and those after it stay ticked. Dragging a note to another place in the sidebar counts as one of those changes, and its **Undo** as one more. Making a folder by dropping a note on another note counts up to 7 when it works — up to 5 tries at creating the folder, when the name it picked turns out to be taken, and one for each of the two notes — and its **Undo** up to 3 more: one for each note moved back, and one for deleting the folder, which isn't counted when the folder is kept because, in **My notes** or **Groups**, notes outside the trash were already in it. Renaming it in the **Rename folder** box that opens after it counts one more each time you save a changed name; pressing **Save** with the name as it was counts nothing.
- **Dragging notes in the sidebar needs a mouse or a similar pointer.** The sidebar takes over a drag only when the browser reports that the device's main pointer is precise and can hover, as a mouse is; where the main pointer is a touch screen, as on most phones and tablets, dragging a note — with a long press too — doesn't move it. Only notes can be dragged, one at a time: dragging a folder doesn't move it, and in the sidebar's selection mode, where several notes can be ticked, dragging doesn't move notes. A note can be dropped only within its own space — **My notes**, **Shared with me**, or in **Groups** its own group.
- **Making a folder by dropping a note on another note isn't all or nothing.** The folder is created first and the two notes are then moved into it, each with its own request. When one of those fails, the app tries to move back what it moved and to delete the new folder if it is still empty, but if that fails too — for example when what failed was the limit of 600 changes to folders a minute — or the tab is closed partway, an empty folder, or one with only one of the two notes in it, can be left. Its **Undo** moves both notes back and then deletes the folder only if nothing else is in it (in **My notes** and **Groups**, notes in the trash don't count); otherwise the folder stays, with the message "The folder has other items now, so it was kept".
- **Dragging can't be done with the keyboard or a screen reader.** Move a note with **Move to…** in its `⋮` menu or **Move to** in the sidebar's selection mode instead; to put two notes in a new folder, create the folder first — **New folder**, or **New subfolder** in a folder's `⋮` menu — and move both notes into it.
- **When a deleted group's notes are given to an admin and the group's name is nothing but control characters, the new folder is named 群組 when the browser's preferred language is Chinese and Group otherwise** — the browser's own language setting, not the language picked in Knotebook's menu.
- **Folder names in the same place are unique ignoring letter case; for letters outside ASCII, what counts as the same letter depends on the database's locale.**
- **In a narrow sidebar, deeply nested folders and notes can lose their names to the indentation, have their right-hand side cut off by the sidebar's edge, and show a folder row's icons on top of its buttons.** On a wide screen, widening the sidebar fixes it; on a phone (under 640 pixels) the sidebar is the whole screen wide, and from 640 pixels the drawer follows the sidebar width setting, so only the docked sidebar can be widened.
