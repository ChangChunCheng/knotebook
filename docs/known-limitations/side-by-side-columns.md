# Side-by-side columns

Rows of columns in the editor, in presentations and over the API and MCP. Part of [Known limitations](../known-limitations.md).

See [Side-by-side columns](../columns.md) for how columns work. In the examples, `[aa | bb | cc]` is a row of three columns holding *aa*, *bb* and *cc*.

- **Columns line up at the top, so a shorter column leaves blank space below it.** A row is as tall as its tallest column; nothing stretches the shorter columns to match.
- **Blocks in a column have no `+` button.** Hovering a block in a column, including a block nested under one, shows only ⋮⋮: the space between columns is too narrow for both buttons. To add a block in a column, press Enter at the end of a block there (or with an image selected, to add a paragraph below it in the same column), or type `/` in a block that has text and pick a block type: the new block goes below it.
- **A heading inside a column doesn't start a section.** Over MCP it isn't a section of its own and isn't listed by `read_note_outline` — the row belongs to the section before it. In a presentation it doesn't start a new slide, and in the editor it has no "#" button for copying a link to it.
- **Removing or replacing what is in a column never removes the column.** When you delete an image in a column (with ⋮⋮ **Delete** or the image toolbar), have the in-app AI rewrite blocks inside one column, or paste a diagram into a column, the row keeps all of its columns: a column left with nothing keeps an empty paragraph, and an empty column elsewhere in the row stays too. When a selection reaches across columns, or into or out of a row (including selecting the whole note when it has a row), the in-app AI works on whole top-level blocks instead: each selected block counts as the top-level block it belongs to, so the action gets the entire row — and the whole of any block whose indented child is in the selection — and its result replaces them; the row stays only if the result has it. Moving a column's only block out with Ctrl+Shift+↑ or ↓, or by dragging it with ⋮⋮, also leaves an empty paragraph behind — except that dragging the only block out of a column in a row of three or more columns removes that column. To remove an empty column, press Backspace at the start of it, or use **Ungroup columns** to turn the whole row back into ordinary blocks.
- **A selection that only touches a row at its edge also makes the in-app AI work on the whole row.** A selection that ends at the very start of the row's first column — dragging from a paragraph above the row to the start of the next line, for example — or starts at the very end of its last column includes the row, though none of the row's text is selected, so the action rewrites the whole row. With a "direct" action, when nothing in the row is an image, video, audio or file, that happens without a preview; **Revert** or Ctrl+Z undoes it.
- **When a selection that starts inside a row taller than the window opens the AI box, the box can be out of view.** While you type an instruction, while the response streams in and when it fails, the box sits just above or below the blocks the action works on — here the whole row — so when neither the top nor the bottom of the row is on screen, the box isn't either. The keyboard focus is in the box, and Esc closes it; scroll up to the top of the row to see it. A finished result shows at the top of the note's scrolling area as usual. The same happens when the first selected block is itself taller than the window.
- **Deleting a selection that spans columns leaves the columns in place.** With ⋮⋮ **Delete** on any block inside the selection, only the selected blocks are deleted (a block's nested blocks go with it; opening ⋮⋮ on one of those nested blocks deletes only that nested block, unless the selection covers the whole row); a column the selection empties keeps an empty paragraph, and the row keeps its number of columns. Use **Ungroup columns** to remove the empty columns. A selection that starts above the row and ends below it deletes the row. Opening ⋮⋮ on a block outside the selection deletes only that block.
- **Backspace and Delete remove a column only when it is empty, with two exceptions.** Backspace at the start of an empty column, or Delete at the end of the column before it, removes that column; when one column is left, the row turns back into ordinary blocks. The exceptions follow the editor's own rules: deleting a table in a column with the keyboard (select all of it, then Backspace) removes every empty column in the row, including that column when the table was its only block; and Delete in an empty code block removes the code block, and its column too when the code block was the only block there.
- **Some Backspace and Delete presses move a block into or out of a row.** Backspace at the start of the first column, or Delete at the end of the block just above the row, moves that block out, above the row, and removes every empty column in the row as well; when the row has two columns and the first holds only that block, the whole row turns back into ordinary blocks. Backspace at the start of the block just below the row, or Delete at the end of the last column, moves that block into the last column. Delete at the end of a block nested under the first column's last block joins the paragraph below the row onto it, skipping the other columns.
- **Selecting across columns and then deleting or typing removes the columns in between.** What is left of the first and the last selected column is joined in the first column, and an empty column takes the place of the rest: selecting from the middle of *aa* to the middle of *cc* in `[aa | bb | cc]` and pressing Backspace leaves `[ac | empty]`. Typing over such a selection does the same, with what you typed in between.
- **Copying part of a row and pasting it outside the row can make a new row.** When the copied part runs from one column into another, pasting it at the top level of a note gives a new row of columns rather than ordinary blocks. When you paste a paragraph, a row and another paragraph together, the first paragraph doesn't join the paragraph at the cursor, and pasting at the start of a paragraph that has text adds an empty paragraph.
- **Copying a row to another app flattens it in the plain-text copy.** The clipboard's plain text, which is Markdown, has the row's blocks one after another — the first column's, then the second's, and so on — with no image widths or table column widths; only the HTML copy keeps the row's column markers. An app that pastes plain text, such as a text editor, gets the flattened form.
- **Editing a row while someone else edits the same row can lose their typing.** When someone removes or flattens columns with the keyboard, presses **Ungroup columns**, or moves blocks by dragging or with Ctrl+Shift+↑ or ↓, what another person types in those places at the same moment can disappear or end up in a different paragraph. When two people at the same moment each delete one of the last blocks of the same column, leaving it empty, the whole row can disappear, other columns included. Being offline and reconnecting counts as the same moment. Dragging with ⋮⋮ has three cases of its own: when you drag a block beside another one to make a row, what another person types in the block you dropped next to at the same moment can disappear, or, when the new row is the last block of the note, appear in the empty paragraph added after it; when you drop a block into an empty column, what another person types in that column's empty paragraph can appear inside the block you dropped; and when you drag out the only block of a column, what another person types in that block can appear in the empty paragraph it leaves behind. A version saved before the edit can be brought back from version history.
- **Two people adding a column to the same row at the same moment can end up with five columns.** When two people each drag a block to the side of a different column of the same three-column row at the same moment, both columns are added and the row has five, over the four a drag allows. Both people see the same row.
- **A pasted row keeps all of its columns, even more than four.** `/grid` makes at most four columns, but a row with more columns pasted at the top level of a note is pasted as it is. Over MCP and the API such a row reads back with all of its columns, but writing it back unchanged is refused with `unsupported_columns`: a write takes rows of 2 to 4 columns.
- **Making columns by dragging is meant for a mouse.** On a touch screen, dragging a block beside another one isn't supported and may not make columns; make a row with `/grid` instead. Pasting a copied row, or part of a row that runs from one column into another, at the top level of a note also makes one.
- **Dragging a column's only block to the side of another block in the same row leaves an empty column.** The column it came from is not removed: it keeps an empty paragraph. Dragging the third column's block to the left edge of the first column of a three-column row gives four columns, the last one empty. Use **Ungroup columns**, or Backspace at the start of the empty column, to get rid of it.
- **The columns of a row of four can't be reordered by dragging.** The drop guide doesn't turn vertical on a row of four columns, so dropping at its edges is an ordinary move, even for a block that is already in the row.
- **Equal heights for pictures are worked out only when a drag makes the row or adds the column, and small pictures aren't enlarged.** A picture that is smaller than the width it would be given keeps its own width; the other pictures still come out the same height.
- **Holding Ctrl (⌥ on a Mac) while dragging a block copies it and doesn't make columns.**
- **Dropping a block beside another one has no keyboard shortcut.** Use `/grid` with the clipboard, or move the block with Ctrl+Shift+↑ or ↓.
- **Dragging an already-selected image by the picture itself doesn't make columns.** It moves like an ordinary block; take it by its ⋮⋮ instead.
- **In the gap between two columns, the guide you see can differ from where the block lands.** While a block dragged by its ⋮⋮ is held over the gap, the guide can be drawn at the top of the left column while the block lands at the bottom of that column.
- **While something is being dragged, the formatting toolbar and its own pop-ups don't accept drops.** Text dragged onto an open **Create link** or embed URL field can't be dropped into it.
- **Making an image in a column smaller doesn't make the column narrower again.** Dragging the image's handle past its column's width widens the column and squeezes the others; once you let go, making the image smaller again leaves the column as wide as it became. Drag the divider between the columns to narrow it.
- **An image can't be dragged wider once the other columns are down to their minimum widths.** The other columns give up width only as far as 200 pixels, or 96 for a column that holds only images; past that the handle stops.
- **Every divider between columns is a Tab stop, so a note with many rows needs extra Tab presses to get past them.** The dividers come after the note's text in the Tab order, one stop each, from the top row down.
- **When two people resize the same row at the same moment, one person's change can be lost.** Dragging a divider changes only the two columns next to it, so two people dragging different dividers keep both changes. When both drag the same divider, the row ends up as the person who lets go last left it. When one widens an image while the other drags a divider, letting go of the image last leaves the whole row as the image's user left it, while letting go of the divider last sets the two columns next to it and keeps the other person's widths in the other columns: a column not next to the divider is changed only if it still has the width it had when the divider was grabbed. When both let go before either has received the other's change (for example while one of them is offline), a column both of them changed keeps one person's value.
- **In a presentation, whether a row stacks is decided when its slide is shown.** That happens when the presentation opens, when you move to a slide, and when a slide's content changes. Resizing the window or switching to full screen doesn't redo it for the slide on screen; move to another slide and back, or reopen the presentation.
- **Columns in a presentation have no minimum width.** They keep the width ratio they have in the note, so in a row whose columns differ a lot in width, the narrow ones can get very narrow before the row stacks.
- **Rolling back to an earlier version deletes side-by-side columns, together with what is in them.** An earlier version doesn't know about columns, so the first time a note with columns is opened there, its rows and everything inside them are removed from the note, and the note is saved that way. Back up before rolling back.
