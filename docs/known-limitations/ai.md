# AI actions in the editor

AI providers and their keys, the built-in and custom AI actions, and the AI box. Part of [Known limitations](../known-limitations.md).

- **An administrator can still obtain AI provider API keys, just not silently.** A provider's key is sent, in plaintext, to whatever host its Base URL names — that is what configuring a provider means. Changing the Base URL therefore clears the stored key, so a key entered for one host cannot be redirected to another. What remains is the slower path: an admin points a provider at a host they control, and waits for someone to enter a key again. That leaves traces — the provider is marked as having no key in Settings, and the server logs `AI provider 的 base URL 被寫入` (on every edit that includes a Base URL, whether or not it changed; creating a provider does not log it) with the account that did it and the old and new target — but nothing prevents it. Do not rely on noticing the URL itself: it is shown truncated, and `https://api.openai.com@evil.com/v1` reads as the real thing at a glance. **The log line is the trustworthy trace** — specifically its `to` and `hasKeyAfter` fields, which come from the write itself; `from` is read separately and can lag under concurrent edits. Separately, because Base URL is deliberately unrestricted (so that you can point a provider at a host on your own network), an admin can also make the server issue requests to arbitrary addresses, including ones only it can reach; the response body is never returned to them, but whether the request succeeded is observable. **Administrator is the highest privilege level in Knotebook; treat it as equivalent to holding every configured provider key.**
- **An error response from the AI provider is written to the server log, and a gateway that echoes credentials in it puts them there.** When a provider answers with a non-2xx status — during an AI action, or when you test a provider's connection in Site admin — the server logs the status and the first 2,048 characters of the response body at `warn` level (the body is never sent to the browser). Most providers' error bodies hold only a message, but a few gateways and proxies repeat the `Authorization` header or part of the key in them, and then that text lands in the log. Only someone who can read the server's logs sees it; the Knotebook log line does not carry the key itself. If you ship logs to another system, treat them as sensitive, or filter the provider-error lines (`upstreamBody` on AI actions, `body` on the connection test) before they leave the host. Tracked in [issue #211](https://github.com/sw-willie-wu/knotebook/issues/211).
- **A deleted built-in AI action reappears on the next server restart.** The five built-in AI actions (rewrite/translate/summarize/continue/instruct) are re-created idempotently on every startup if missing. Renaming or disabling a built-in action persists normally — only deletion is undone. If you don't want a built-in action available, disable it (or rename it to repurpose it) rather than deleting it.
- **The Instruct action's guard is a prompt, not a filter.** The instruction, the highlighted characters and the selected text are put inside fixed tags without any escaping, so text that itself contains something like `</text>` can blur where one part ends, and whether an instruction is off-topic is left to the model. The guard tells the model to return the text unchanged for an off-topic instruction, but that isn't guaranteed; when it does, the AI box says there are no changes, which is not an error.
- **The AI's instruction to keep columns and sizes is a prompt, not a filter.** Every AI action asks the model to keep the [side-by-side column](../columns.md) tags and the `width` and `colwidth` values in the text it is given, and a result that writes them in another form is refused. A result that leaves that markup out altogether passes the checks, though: applying it replaces the blocks it was made from like any result, so a row it was given turns into ordinary blocks and the image widths and table column widths it left out are gone. **Revert** (after a "direct" action) or Ctrl+Z undoes it. See [AI](../ai.md).
- **A selection that includes or is inside a code block shows no formatting toolbar, so the AI box can't be opened on it.** This comes from the editor's toolbar rule, which hides the toolbar whenever a selection includes or is inside a code block — including Ctrl+A on a note that contains one. To run AI on such a note, select the parts around the code block one at a time.
- **If the code for the AI box's preview fails to download, a result you haven't applied yet is lost.** The preview is loaded on demand together with version history; when that download fails the page reloads to fetch it (automatically at most once after each successful load; after that, its **Try again** button reloads the page), and the reload discards the AI result that was waiting in the box.
- **On touch screens, custom AI actions in the AI box have no visible name.** The built-in actions have their own icons; custom actions share one generic icon whose name shows only as a mouse tooltip or to screen readers.
- **The AI box's result covers the text below the selected blocks until you close it.** When a response finishes, the box moves on top of the selected blocks and extends downward over the paragraphs that follow; to read them, apply, discard or close the result first.
- **The AI box's result stays at the top of the note's scrolling area once the selected blocks scroll up out of view.** It keeps covering whatever note text is there, even after the selected blocks have scrolled away entirely, until you apply, discard or close it.
- **The AI box takes the width of the first block it works on.** That is the first selected block — or, when a selection reaches across [side-by-side columns](../columns.md) or into or out of a row and the action works on whole top-level blocks, the first of those, so when such a selection starts inside a row, the box is as wide as the whole row. Its preview wraps lines like the note does for that block, but when a selection spans blocks at different indent levels, the other blocks may wrap differently in the preview than in the note.
- **When the AI box's preview is taller than the box, a scrollbar can make its lines wrap differently than in the note.** The box is at most 40% of the window's height and scrolls beyond that; on systems whose scrollbars take up space instead of overlaying the content, the scrollbar narrows the preview, so a long result may wrap at different points than the same text in the note.
- **In the AI box's preview, code blocks show no coloured bar for added, removed or changed blocks.** The bar is drawn as an inset shadow on the block, and the code block's full-width background paints over it; the strike-through and fading of removed blocks still show. The version history panel marks blocks with a left border instead and is not affected.
- **The AI box's instruction field grows with its text, up to four lines, in browsers that support CSS `field-sizing: content`.** Firefox doesn't as of October 2026, so there the field stays one line tall and scrolls inside itself.
- **AI quick-action requests are rate-limited to 30 per user per minute by default (a site admin can lower it), in-memory.** Like the other in-memory limiters in [Limits](./limits.md), this counter lives in process memory and resets whenever the `app` container restarts (and can't be shared across instances — see the [single-instance warning](../self-hosting.md#single-instance-warning)).
- **AI quick actions round-trip your note content through Markdown, which can lose fidelity.** The selected block(s) are serialized to Markdown before being sent to the AI provider, and the response is parsed back from Markdown into blocks; formatting that doesn't survive that round-trip cleanly (e.g. some nested structures or block-specific attributes) can be altered by running a quick action over it, independent of anything the AI itself changed.
- **Anthropic responses are capped at 4096 output tokens (`max_tokens`), with no error on truncation.** If a quick action's response hits that limit, Anthropic's API stops generating and Knotebook streams whatever was produced without surfacing an error — long outputs (e.g. "continue" on a lengthy selection) can be silently cut off mid-sentence. This is a fixed server-side constant today, not yet a configurable setting.
