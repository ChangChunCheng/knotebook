# Changelog: 0.5

Releases in the 0.5 series of Knotebook. Newer releases and changes not released yet are in [CHANGELOG.md](../../CHANGELOG.md).

## [0.5.0] - 2026-10-05

### Upgrade notes

Read these before upgrading from 0.4.x.

- **Back up the database first — this upgrade can't be undone.** This release's database migrations (0011–0013, which add groups) run automatically when the new server starts, and there is no way to reverse them. Take a dump before you start the new version, for example `docker compose exec -T db pg_dump -U knotebook knotebook > knotebook-before-upgrade.sql` — see [Upgrading and rolling back](../self-hosting.md#upgrading-and-rolling-back).
- **Don't go back to 0.4.x on the upgraded database.** A 0.4.x server predates groups: it decides who can open a note only from the note's owner and its per-person shares, and a note that belongs to a group has neither, so no one signing in to it could open a group's notes. To return to 0.4.x, restore the dump you took before upgrading into an empty database (the steps are in the same section) — everything written after the upgrade is lost.
- **Changes an existing API or MCP client may notice:**
  - MCP results (`list_notes`, `search_notes`, `create_note`) say whose note it is in an `owner` object instead of an `ownerHandle` string — see **Changed** below.
  - REST note objects can now be group notes. On a group note `ownerId` and `ownerHandle` are `null`; new fields — `groupId`, `group: {id, name}` and `permissions` (what you can do with the note) — are on every note object. A client that builds `/n/<ownerHandle>/<slug>` links needs `/g/<groupId>/<slug>` for group notes. `GET /api/notes` now also returns the notes of every group you belong to, and a `GET /api/notes/:id/backlinks` entry has `ownerHandle: null` and a `groupId` when the linking note is a group note. See the [API contract](../api.md).
- **Only if your server ran a pre-release build with groups** (a build of the `main` branch from after #103 and before migration 0012 — no released version had groups): the migration hands every group note over to its group — notes that were read-only for their group become editable by every member, and the group's admins can now delete them, manage their public links and change their URL name — removes the per-person shares, custom public URLs and previous-name redirects on those notes, renames a note whose URL name clashes with another in the same group (normally with a numeric suffix), and forwards each one's current `/n/…` address to its new `/g/…` address for a month. Which notes were read-only for their group, and who owned each group note, can't be recovered afterwards. If you go back to that build after upgrading, it still starts on the migrated database but can't serve notes any more — loading a note or the note list fails with a server error — because columns it reads are gone; restore the dump instead. That build's groups API changed too: `DELETE /api/groups/:id` now requires a body (`{mode: "transfer", transferTo}` or `{mode: "delete"}`) and answers `400 invalid_body` without one; the member endpoints take a `roleId` instead of `role: "admin" | "member"`, members are listed with `roleId` and `builtin`, and a group's `myRole` is a role object instead of a string; a note object's `group` no longer carries a `role`; and `PUT`/`DELETE /api/notes/:id/group` are gone — a note joins a group with `POST /api/notes/:id/move`, and no endpoint takes a single note out of a group.

### Added

- Groups (#103, #175): a group owns its notes. A note created in a group belongs to the group, not to a person — it lives at `/g/<group id>/<name>` (the name is unique within the group), and what each member can do with it comes from their role in the group. The sidebar gains a collapsible **Workspace** section with one section per group (each with a `⋮` menu, and a "new note here" button when your role can create and edit notes), and the other three sections (Recent, My notes, Shared with me) can be collapsed too. **Settings → Groups** lists your groups and, per group, its members — people whose role allows it can rename the group, add and remove people, and change their roles; anyone except the group's last admin can leave. See [Sharing](../sharing.md).
- Group roles (#175): every group starts with two roles: **Admin** (can do everything — edit and delete any note in the group, turn its public links on and off, give a note a custom URL name through the API, manage members and the group itself) and **Member** (can read, create and edit notes). People whose role allows it can define more roles on the group's **Roles** tab in **Settings → Groups**, choosing any of six permissions for each (every role can read the group's notes); the built-in Admin role can't be changed, and deleting a role moves its members to Member.
- The Share dialog on a group note has no per-person sharing: it explains who has access and links to the group's settings, plus a **Public link** switch when your role can manage public links (a group note has no custom public URL) (#175).
- Moving and copying notes (#175): an existing personal note can be moved into a group (its per-person shares and public link are removed, and its old address forwards to the group address for a month) or copied into one, and any group note you can read can be copied to your own notes — a copy gets its own copies of the note's attachments, which count against your upload limit. No single note can be moved out of a group (deleting a group can give all of its notes to an admin).
- Deleting a group (#175) either gives all its notes to one of its admins — they become that person's personal notes, their public links are turned off, and their old `/g/` addresses forward that admin to them for a month — or deletes the notes with it.
- Groups over the API and MCP (#175): every note response (`NoteDto`) now reports what you can do with it in a `permissions` object, and `GET /api/notes/by-group-path/:groupId/:slug`, `GET /api/groups/:id/roles`, `POST /api/groups/:id/roles`, `PATCH /api/groups/:id/roles/:roleId`, `DELETE /api/groups/:id/roles/:roleId`, `POST /api/notes/:id/move` and `POST /api/notes/:id/copy` are new, alongside the group and member endpoints (`DELETE /api/groups/:id` takes `{mode: "transfer", transferTo}` or `{mode: "delete"}`). MCP clients see group notes in `list_notes`/`search_notes`, can edit them when their role allows, and can create a note in a group by passing `create_note` the new `groupId` argument (when their role can create notes there); they can't move or copy notes, and no MCP tool lists your groups — see the [API contract](../api.md), [MCP](../mcp.md) and [Known limitations](../known-limitations.md).
- The sidebar can be resized: drag the gap between the sidebar and the note — or reach it with Tab and use the left and right arrow keys (16 pixels a step), Home and End — to make the sidebar anywhere from 200 to 480 pixels wide; double-click the gap to go back to the default 256. The gap stays invisible until you drag it or give it keyboard focus, when a thin line appears; hovering it only changes the pointer. The width is remembered in this browser. On narrow windows, where the sidebar opens as a drawer, the drawer keeps its fixed width. The width doesn't adapt to the window, so a sidebar widened on a large screen can leave too little room on a small one — see [Known limitations](../known-limitations.md).
- Every note in the sidebar has its own `⋮` menu with the same items as the `⋮` at the top of an open note: **Copy link**, **AI edit history**, on group notes **Copy to my notes**, and, on notes you can delete (your own, or a group note when your role allows it), **Delete note** — so the sidebar can delete notes again. Used on the note you have open, it does what the top-of-note menu does (deleting takes you back to the home page). Used on another note, **AI edit history** opens that note with its history already showing, and deleting it leaves you where you are. Deleting a note from the sidebar while that note is still loading, and screen-reader names for notes that share a title, are covered in [Known limitations](../known-limitations.md).
- A request that has waited 10 seconds for a free database connection now fails with a server error instead of waiting indefinitely, and two optional settings, `DATABASE_POOL_MAX` (default 10 connections) and `DATABASE_POOL_CONNECTION_TIMEOUT_MS` (default 10000), set how many database connections the server opens and how long a request waits for one — see [Self-hosting](../self-hosting.md) (#175).

### Changed

- MCP results say whose note it is in an `owner` object — `{kind: "user", handle}` for a personal note, `{kind: "group", id, name}` for a group note — instead of an `ownerHandle` string (#175).
- The sidebar's `⋮` menus — on groups and on notes — now appear only when you hover over their row or reach them with the keyboard, the same way the small `+` buttons on the Workspace and group headings already did, instead of always being visible; a `⋮` stays visible while its menu is open, and on touch screens they are always shown.
- The last-edited line at the top of a note now reads "Last edited by *name* · *date*" and is set apart from the connection status by a thin divider — it could be misread as naming the note's owner; hovering it shows who and the full date and time. When the top of a note runs short of room (a smaller window, a wide sidebar, the AI panel open), the title gives way first and then this line is shortened with an ellipsis, instead of the **Share** and `⋮` buttons being squeezed; when there still isn't enough room they can be cut off — see [Known limitations](../known-limitations.md).
- Site administration (user management and AI provider setup) moved out of the Settings dialog onto its own page at `/admin/users` and `/admin/ai`, reached from a new **Site admin** item in the user menu that only admins see; it uses the normal app layout, with the sidebar showing the admin sections and a way back to your notes. Settings now holds only Account and Groups, the same for everyone. The old `/settings/users` and `/settings/ai` addresses redirect to the new pages.
- The Settings dialog (Account, Groups) and the site admin pages (Users, AI) now share one consistent layout — a page title and description at the top, groups separated by hairline dividers instead of ad-hoc spacing, and matching type sizes for group titles and body text throughout, instead of each section inventing its own headings and spacing.
- The Share dialog of a personal note is now organized by access level: picking **Private**, **Members only**, or **Public link** shows only the controls that level needs, instead of the member list and public-link controls both being visible regardless of which one is selected. The dialog's icon-only trigger button also now reflects the note's current access level (a lock, a share icon, or a globe; on a group note, a people icon or a globe).
- A personal note's public link now defaults to an anonymous, unguessable URL (`/p/<token>`), controlled by an **Anonymous link** toggle; turning it off switches the same URL to a human-readable, custom form (`/p/<username>/<name>`) instead of adding a second URL alongside the token one. **Regenerate link** now rotates both the token and, when Anonymous link is off, the custom name together, so a leaked custom URL can always be fully retired — not just the token behind it, leaving the same guessable name reachable with a fresh token.
- Buttons and form controls (inputs, native `<select>`s) are now a uniform 32px tall across the app, and buttons follow a single set of variants chosen by how important an action is on the screen it appears on, not by how destructive it is — see the usage notes at the top of `components/ui/button.tsx`.
- Paragraphs, list items, and quotes in the editor are now justified (both edges align to the column), paired with a rule that allows a long, unbroken run of text (a URL, an identifier) to break mid-word so it can't stretch the rest of that line's whitespace to fill the gap.

### Removed

- The Share dialog's internal note-to-note link section (a copyable link plus a custom-slug field, for linking notes within the app) has been removed — link to another note from inside a note with a `[[title]]` wikilink instead; anyone the note is already shared with sees it in their own sidebar without needing a link.

### Fixed

- Hovering a table whose bottom or right edge was outside the window no longer adds a scrollbar or makes the layout jump — neither a page-wide one, nor, for a table too wide for the window, a horizontal one on the note content area. The row/column "add" buttons that appear on hover are positioned with plain CSS absolute positioning, and the note content had no positioned ancestor for them to anchor to, so they escaped every container meant to hold them and anchored to the page itself, which then had to grow to fit them; giving them one contains them, and the note's own scroll container now also clips horizontal overflow directly, so a button wider than the visible area is simply cut off at the edge instead of making the container scroll sideways (#160, #162).
- Uploading an image to a note that is deleted while the upload is being processed now answers `404 not_found` instead of a server error; the uploaded file isn't kept (#175).
