# Changelog: 0.11

Releases in the 0.11 series of Knotebook. Newer releases and changes not released yet are in [CHANGELOG.md](../../CHANGELOG.md).

## [0.11.1] - 2026-10-15

### Changed

- Links in the editor now behave like links elsewhere. Clicking a link to a note while editing opens it, the same as when reading (it used to open a small toolbar with an **Open** button); its toolbar — **Edit text**, **Change target**, **Remove link** — now opens when you hover over the link, and the **Open** button is gone. On a touch screen, a tap opens a link; while editing, pressing and holding a link for about half a second opens its toolbar instead of the system's link menu, for ordinary links as well as links to notes (read-only and public pages keep the system menu).

### Fixed

- The version history panel's resize handle now sits in the gap between the note and the panel, like the sidebar's, instead of inside the panel card (#274).

## [0.11.0] - 2026-10-15

### Upgrade notes

The full checklist is under **Upgrading to v0.11** in [Upgrading and rolling back](../self-hosting.md#upgrading-and-rolling-back).

- The first start after upgrading adds the **Instruct** action, enabled, with no model of its own, so it uses the same model as any other action without one: the default model, or, when no default is available (none is marked, or it or its provider is disabled), the earliest-added enabled chat model. On any site where AI actions already work, every editor can send free-form instructions right away, whether or not a model is marked as the default; disable the action in **Site admin → AI agents** if you don't want that.
- On a new install, the built-in **Rewrite** and **Translate** actions show a preview first, like the other built-in actions, instead of applying directly. Upgrading doesn't change an existing site's actions: there, Rewrite and Translate keep the apply mode they have — direct, unless an admin changed it — and an admin can switch them to preview under **Apply mode** in **Site admin → AI agents**.
- If you roll back to 0.10, the Instruct action stays in the database and 0.10 lists it as an ordinary quick action that only fills in `{{text}}`: the literal `{{instruction}}` and `{{focus}}` would reach the model, without the guard. Disable the action before rolling back (#263).
- Migration 0024 adds the time each account was last active and fills it in from the last sign-in time, so after the upgrade **Last active** shows when someone last signed in until they next use the site. Accounts with no recorded sign-in show **Not recorded** until then. Rolling back to 0.10 is harmless for the database: 0.10 doesn't read or write the new column.
- Automatic versions are now saved only after a note has had no new changes for a while — 5 minutes by default, set in **Site admin → Storage plans → Keeping automatic versions** (1–60 minutes); the version appears within about half a minute after that. Leaving a note, and AI or API writes, no longer save a version straight away: an AI write and the edits around it go into the same version once the note goes quiet. Save a version by hand (Ctrl+S) if you want a cut at a particular point. Migration 0025 adds the pending-change columns, the wait setting and the id of each version's base (filled in for bases that still exist). Changes the previous version had not saved as a version when it stopped are saved after the next edit. Rolling back to 0.10 is harmless for the database: 0.10 doesn't read the new columns; in rare cases a note moved while on 0.10 can get one extra automatic version after upgrading again. After upgrading again, a note whose base changed while on 0.10 can show the wrong base under **Current state** (the one it had at the rollback, or **a deleted version**) until a new version is saved or a version is applied, and versions saved on 0.10 on top of an older version keep showing as based on **a deleted version**.
- **Reload every open tab after upgrading.** Tabs opened before the upgrade can't connect to the new server: they keep retrying in the background ("Connecting…", then an offline warning), and edits made in them that hadn't synced are lost when you reload. From now on, when an upgrade changes how the editor stores notes, a tab opened before it shows a notice asking you to reload instead (#269).
- Migration 0026 records every note that exists at that moment, and about 30 seconds after the first start the server turns ordinary links to notes on this site in those notes into links to the notes, in the background — with the owner's permissions, and in a group note only links to notes in the same group. Notes created after the upgrade are not processed. Before changing a note it saves a version named `連結轉換前` (or, if the content is already the note's base version, turns that version into a manual one, keeping its name if it has one — see [Versions](../versions.md)); to undo the conversion for one note, apply that version — its links come back as ordinary links and the conversion doesn't convert them again. Progress is in the `app` log; see [Self-hosting](../self-hosting.md#upgrading-and-rolling-back) (#269).
- Rolling back to 0.10 after migration 0026 is harmless for the database: 0.10 doesn't read the new table. But 0.10 doesn't know a link's own text or the paragraph it points to: on 0.10, moving or splitting a block that holds such a link (or moving one next to it), or copying and pasting the link, can drop them, and MCP and the API read the link as `[[…]]` with the title saved in the link, so writing that back binds it again by title alone, if at all; 0.10 also doesn't ask tabs opened on this version to reload, so they can still connect and edit (#269).
- After rolling back to 0.10 and upgrading again, 0026 doesn't run a second time and the conversion only picks up notes still waiting for it, so it doesn't convert ordinary links to notes added on 0.10 in any other note, including notes created on 0.10 (#269).
- Moving a paragraph that holds a link to a note made before the upgrade, or a block next to it, can change that section's MCP fingerprint once, even though its text didn't change; an AI client's next `if_match` on that section then gets a fingerprint mismatch and has to read the section again (#269).
- `[[Title]]` written over MCP or the API is now also bound inside tables (#269).

### Added

- Site setting for how long to wait after the last change before saving a version automatically (#272).
- AI on a selection: the **AI** button on the formatting toolbar now opens a box in place of the toolbar, where you can type your own instruction for the selected text or pick a quick action. When the response finishes, the result appears over the selected blocks — covering the text below them until the box closes — as an inline diff of only those blocks. Instructions and preview actions wait for you to apply, discard or retry, while direct actions apply as before and can be reverted (#263).
- A fifth built-in AI action, **Instruct**, carries those free-form instructions. It always shows a preview first, and the server wraps it in fixed tags and a fixed guard that admins can't change (#263).
- Links to notes: a link to a note on this site that you can see — pasted, typed as Markdown, typed as an address, inserted with the link dialog, or written by an AI client — is saved as a link to that note: it follows renames, shows up in backlinks, opens in the same tab, and can have its own text. Clicking one while editing opens a small toolbar to open it, edit its text, change its target or remove the link, leaving its text (#269).
- Links to a paragraph: an address ending in `#b-<block id>` opens the note scrolled to that block and highlights it briefly. **Copy link to block** in the drag-handle menu and a "#" button beside headings copy such a link (#269).
- MCP and the API read links to notes as `[text](/notes/<id>)` (ending in `#b-<block id>` when they point to a place), and save a Markdown link to a note you can see as a link to that note (#269).
- Public pages link to other notes that are public under a custom URL; `GET /api/public/notes/…` returns them in `links` (#269).
- The version history panel on wide screens can be resized by dragging its left edge (240–560 px; double-click the edge to reset to 320 px, or use the arrow keys when it has focus). The width is remembered in this browser (#274).

### Changed

- Versions are no longer shown as v1, v2…: each is identified by its name and the first 7 characters of its id; a version nobody named gets a generated two-word English name. A version based on one that was deleted since says so (#272).
- Non-revertable rows in the AI edits dialog say why, and the dialog notes how many AI edits each note keeps (#272).
- The admin AI actions list and `GET /api/ai/actions` include each action's `kind` (`"instruct"` or `"quick"`); `PATCH /api/admin/ai/actions/:id` refuses to set the Instruct action to `direct` (`instruct_preview_only`) (#263).
- **Breaking (API):** `POST /api/ai` takes `instruction` and `focus` for the Instruct action and now rejects them with 400 for any other action; they used to be silently dropped (#263).
- Version history: each window width now has one way in. The `⋮` menu at the top of a note no longer has **Save current version** (use Ctrl+S, or the button at the bottom of the version list), and shows **Version history** only on a narrow window, where there is no round button at the bottom right.
- Site admin → Users: the **Last sign-in** column is now **Last active** — when someone last used the site while signed in: a request from the browser, opening a note for live editing or typing in one, or signing in — shown as **Online** when that was less than 5 minutes ago, otherwise as the date and time, or **Not recorded**. Requests made with an API token or a connected app don't count. **Online** is not a live connection status; see [known limitations](../known-limitations.md) (#267).
- API: `GET /api/admin/users` also returns `lastActiveAt`, when each user last made a signed-in request from the browser, opened or edited a note over the live editing connection, or signed in (`null` if never recorded); `lastLoginAt` is still returned (#267).
- Lists in Settings, a group's panel and Site admin now share one table layout: the name column first, then the details, then the controls, with each row's buttons and its **Enabled** switch at the right end and lined up from row to row, including the models listed under each AI provider, whose buttons and switches line up with the provider's. On a narrow screen a table scrolls sideways inside its own frame while its name column stays in place (the models' names, and the text under a row, scroll with the table), and the panel itself no longer scrolls sideways; when the table doesn't fit, its frame can be reached with Tab to scroll it from the keyboard. The **Providers** list in **Site admin → AI agents** and the **Sign-in services** list in **Site admin → Sign-in** no longer switch to a stacked layout on narrow screens. When a button or switch partly hidden under the name column gets focus, the table scrolls so it is no longer covered; with the mouse, a table with four buttons a row (**Actions** in AI agents, **Sign-in services**) scrolled all the way right on a narrow screen can still have part of a row's first button under the name column — scroll back a little. For screen readers, each list is now a table whose rows are named after their item: AI provider and sign-in service names are no longer headings, so moving by heading no longer jumps between them, and the column headings of those two lists, which used to be hidden from screen readers, are now read as column headers.
- **Site admin → Users:** the columns now read User, Email, Storage, Last active, Role, Plan, Enabled (Role and Plan used to come right after Email). An error from changing someone's role or turning their account on or off now shows on a line of its own under their row instead of under the **Role** menu.
- **Site admin → AI agents:** an action's apply mode and model are now in **Apply mode** and **Model** columns instead of a line under its name, its move up/down buttons are arrow icons with the same names as before, and its switch no longer has an **Enabled** label beside it (the column heading says it). A model's ID is now under its name, and its switch comes after its buttons. The model and action switches are now announced as "Enabled" followed by the model or action name, like the other lists.
- **Site admin → Sign-in:** a sign-in service's row buttons are now in the order Test connection, Icon, Edit, Delete (Icon used to come after Edit), matching the order used in every other list: test and secondary actions first, then edit, then the destructive one. A long issuer URL is now cut to one line; point at it to see all of it.
- **Settings → Sign-in → Sign-in methods:** when each sign-in service was linked and last used are now in **Linked** and **Last used** columns instead of lines under its name. When one can't be unlinked because it is the only way to sign in, its **Unlink** button can now be reached with Tab and shows the reason when you point at it, besides the reason written under the name.
- **Settings → Authorization → API tokens:** a token's creation date now comes before an app's "Name is self-reported…" note, and long names wrap instead of staying on one line. While one token is being edited, the other tokens' pencil buttons can be reached with Tab and show "Finish editing the other token first." when you point at them, instead of being skipped. While editing, **Save** and **Cancel** are check-mark and cross icon buttons at the right end of the row, and the row's **Last used** and **Expires** are hidden until you're done.
- In a group's **Roles** page, **Save** and **Cancel** for renaming a role are check-mark and cross icon buttons. The **Actions** heading over the buttons in **Site admin → Storage plans** and a group's **Members** page is now read only by screen readers, like the other lists. The **By type** rows in **Settings → Storage** and a group's **Storage** page, and its **By member** rows, now have the same spacing and dividers as the tables.
- Searching finds a link to a note by its own text, or by the text it was made with; notes are indexed again in the background after the upgrade (#269).
- Version comparisons and the AI box's preview show links to notes by their text, and mark a link whose target, the place it points to, or its own text changed (#269).
- Public pages no longer request the signed-in note list (#269).

### Removed

- The AI panel and the round AI button at the bottom-right of the note page, together with running an action over the whole note from them. Select everything with Ctrl+A and use the toolbar instead (#263).

### Fixed

- Copying a selection that contains a link to a note (one made with `[[`) no longer leaves the clipboard empty (#269).
- Typing in the title right after creating or opening another note could rename the note you were leaving. While the next note is still loading, the old title box now ignores typing.
