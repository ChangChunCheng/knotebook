# Changelog: 0.14

Releases in the 0.14 series of Knotebook. Newer releases and changes not released yet are in [CHANGELOG.md](../../CHANGELOG.md).

## [0.14.1] - 2026-11-02

### Changed

- **Notes with Mermaid diagrams open faster.** A diagram is drawn only when it comes near the visible part of the note, one at a time with a pause between them so typing and scrolling stay responsive, and shows **Rendering diagram…** until it is drawn. A diagram already drawn in this tab (same source, same theme) appears at once when you come back to the note or open the presentation. Switching the theme redraws diagrams far from view only when you scroll to them.

### Fixed

- **Moving many notes into a folder at once no longer stops after 30.** Creating, renaming, moving and deleting folders and filing notes in them — in the web app and with MCP's folder tools — now count against their own limit of 600 a minute per person instead of the 30-writes-a-minute limit that edits, copies and versions use, so doing so no longer uses up the budget for AI edits. Moving a selection in the sidebar now stops with "Too many requests" after about 600 in a minute (sooner if you've made other changes to folders in that minute) rather than after 30; its **Undo** counts against the same limit, so it can still stop partway when the move and the **Undo** together pass it. See [Known limitations](../known-limitations.md#folders).

## [0.14.0] - 2026-11-01

### Upgrade notes

- **Notes with side-by-side columns read differently** over MCP and the REST API: a row now reads as `<div data-kb-columns …>` and `<div data-kb-column …>` lines with Markdown inside each column. Before, a row read as its columns' blocks one after another, without the column tags (or, when a block in the row had a color, as one block of HTML). Writing back that flattened text read from an earlier version still turns the row into ordinary blocks. See [AI editing](../ai-editing.md#columns).
- **Notes with a resized image or with table column widths read differently** over MCP and the REST API, and the in-app AI gets them in the same form: an image with a set width now reads as `<figure><img … width="W">…</figure>`, and a table with column widths as an HTML table with `colwidth` on its first row's cells, instead of `![name](url)` and a Markdown table. Two forms that were already HTML are stricter: a colored table with column widths used to have `colwidth` on every row, and a colored image with a set width carried more attributes than the `<figure>` form allows; writing back such text read from an earlier version is refused with `unsupported_size`. See [Sizes](../ai-editing.md#sizes).
- **Writes are stricter about sizes and layout.** A `width` on an `<img>` or a `colwidth` not written in the form reading gives, and a `<div>` whose `style` lays it out with `display:flex` or `display:grid` (other than a row or column of side-by-side columns), now reject the whole write with `unsupported_size` or `unsupported_columns`; such a `<div>` used to be accepted and its contents flattened into ordinary blocks. HTML with an event-handler attribute, such as `onerror` or `onclick`, now rejects the whole write with `unsupported_block`; the attribute used to be dropped. This applies to MCP, the REST API and the in-app AI's results. See [AI editing](../ai-editing.md#columns).
- **`DELETE /api/folders/:id` is stricter about its body.** It used to ignore any body it could parse; now any body other than none, `null`, `{}`, `{"onlyIfEmpty": false}` or `{"onlyIfEmpty": true}` — another field, an `onlyIfEmpty` that isn't `true` or `false`, a JSON value other than an object or `null`, or a plain-text body — is refused with `400 invalid_body`, and the folder isn't deleted. A script that sends such a body should send none instead (or `{"onlyIfEmpty": true}` to delete the folder only if it is empty). See [API](../api.md).

### Added

- **Folders** in the sidebar's **My notes** and **Groups** tabs: create, rename and delete folders, nest them up to five levels, sort the notes in a folder by name, last modified or size, and create notes in a folder. Group folders are shared with the group. Deleting a folder asks first, moves its notes to the trash, and **Undo** brings them back into rebuilt folders. **Shared with me** has folders too (**New folder**), seen only by you: filing a note someone shared with you there changes nothing for anyone else, and its folders are removed rather than deleted (their notes go back to the top level). Existing notes are moved into folders in three ways: **Move to…** in a note's `⋮` menu (see **Changed** for how its lists now work); **Move to** in the sidebar's selection mode, where folders can be ticked, moved within their space and deleted (in **Shared with me**, removed) along with notes; and, with a mouse, dragging a note in **My notes**, **Groups** or **Shared with me**. Moving within the same space doesn't ask, and its message offers **Undo**. A dragged note goes into a folder when dropped on the folder or on a note in it, or to the top level when dropped on a top-level note or an empty part of the list, always within its own space (in **Groups**, its own group), and holding it over a closed folder of that space for half a second opens that folder. Holding it for half a second over another note of the same space that you could drag too, unless that note is in a fifth-level folder or deeper, shows a new folder holding both notes in that note's place; dropping it there creates the folder — **New folder**, or **New folder 2** and so on if that name is taken there — with both notes in it and opens **Rename folder** for it, and once that closes, the message offers **Undo**. **Make a copy** in a note's `⋮` menu puts the copy in the same folder as the original. Items in the sidebar's **Trash** tab show the folder each note was in, after its group's name, and the location shown under notes in **Recent** and in search results includes the folder path.
- **Folders over MCP**: `list_folders` pages through the folders you can see, with each one's path, and every credential has it, read-only ones included; with `notes:write`, `create_folder`, `rename_folder` and `move_folder` create, rename and move folders within their space, and `move_note_to_folder` files a note in a folder of its own space — for a note someone shared with you, in your own folders, which only you see; with `notes:delete`, `delete_folder` deletes a folder and the folders in it, moving the notes in your own or a group's folders to the trash (in your folders for notes shared with you, the notes just go back to the top level), and `restore_note` usually brings each note back into a folder at the path it had, re-creating the missing folders on that path. `create_note`, `copy_note` and `move_note_to_group` take a `folder_id`; a group's folders need a role that can edit notes. Folders are given by id, never by path. Every note in a reply — from `list_notes`, `search_notes`, `create_note`, `copy_note`, `move_note_to_group`, `restore_note` and `move_note_to_folder` — carries `folder`, the folder it is filed in for you (for a note shared with you, where you filed it, never where its owner did), and `read_note_outline` carries that folder's whole path. See [MCP](../mcp.md).
- `DELETE /api/folders/:id` takes an optional body `{"onlyIfEmpty": true}`, which deletes the folder only if it is empty: a folder that has a folder in it or, in your notes or a group, notes outside the trash in it, or, in notes shared with you, notes filed in it, answers `409 folder_not_empty` and nothing changes. Without a body, or with `null`, `{}` or `{"onlyIfEmpty": false}`, the endpoint works as before; other bodies are now refused (see **Upgrade notes**). The web app uses it when undoing a folder made by dragging, and when taking one back after making it failed partway. MCP's `delete_folder` doesn't take it. See [API](../api.md).
- MCP, the REST API and the in-app AI read and write side-by-side columns as `<div data-kb-columns …>` and `<div data-kb-column …>` lines with Markdown inside each column (see [AI editing](../ai-editing.md#columns)); reading used to give the columns' blocks one after another without the column tags, and writing columns was refused. On a selection that reaches across columns, or into or out of a row, the in-app AI now works on the whole row, where it used to show no **AI** button. Dragging to make columns or change their widths is still not part of this. See [Side-by-side columns](../columns.md).
- Add several people to a group at once: on the group's **Members** page, type or paste many email addresses into the email box (separated by commas, semicolons, spaces or line breaks — full-width `，` `；` and `、` work too; `Name <address>` copied from an email's recipients works too), or press **Import from another group…** to pick people from another group you're in. Everyone gets the role picked next to the email box. A dialog counts them as it goes, with **Stop** to end it after the one being added, and then lists who was added, who was already a member, which addresses have no account and which aren't email addresses; the addresses that weren't added are put in the email box. There is no limit on how many at a time. Importing is a one-time copy — the groups don't stay in sync. See [Notes in a group](../sharing.md#notes-in-a-group).
- The email field for adding someone to a group (**Members**) or sharing a note (**Members only**) now suggests people as you type two or more characters of their email or name — only people you already know: members of your groups and people you've shared your own notes with, never everyone on the site. Pick one with the mouse or with ↑/↓ and Enter; typing a full email still works for anyone else. In the group's email box, which takes several addresses, the suggestions are for the address you're typing, and picking one replaces only that address and adds a comma after it unless a comma, semicolon or line break already follows. Backed by the new session-only `GET /api/users/suggest` (at most 8 results, 60 lookups per minute per user). See [Sharing](../sharing.md#the-three-access-levels).

### Changed

- **Move to…** and **Copy to…** in a note's `⋮` menu list places level by level, folders included; before, each was a single list without folders, beside the menu on a wide window with a mouse or under it on a narrow window or a touch screen. On a wide window with a mouse their lists open beside the menu and each folder with subfolders opens its own list beside that one; the first item of a list is **Move here** (**Copy here**) or, for a space, **Top level**, and there is no **Back**. On a narrow window or a touch screen the levels replace one another in place, and **Back**, with a left arrow, goes up a level. Resizing the window across the line while the menu is open closes the menu. The **Move to** and **Copy to** dialog of the sidebar's selection mode also lists places one level at a time. In both, **Top level** has a house icon and **Move here** / **Copy here** a corner arrow, so every item has an icon like the folders, spaces and **Make a copy**.
- **Move to…** in a note's `⋮` menu also appears, when there's somewhere to move the note, on group notes your role can edit, to move them within the group, and on notes shared with you, to file them in your folders in **Shared with me**. Selection mode's **Move to** is now in **Groups** and **Shared with me** too.
- Selection mode on a wide window with a mouse, in the sidebar's tabs and in **Trash**, is one row at the top: **Exit selection** (✕), a **Select all** check box that shows a partly-ticked state, the number ticked (or the progress while a batch runs), and icon buttons for **Move to**, **Copy to** and delete (**Restore** and **Delete permanently** in **Trash**); the buttons at the bottom of the sidebar (and **New note**, or the retention note in **Trash**) are not shown. On a narrow window or a touch screen the buttons stay at the bottom and **Move to** now looks like **Copy to**.
- A **Move to** or **Copy to** that can't be used in selection mode because the ticked notes are in different groups, or because folders are ticked, now shows the reason when you hover it, and a message when you tap it on a narrow window or a touch screen; before, the reason never showed.
- The check boxes in selection mode, in the lists and in **Trash**, are drawn by Knotebook instead of by the browser.
- The sidebar's **Workspace** tab is now called **Groups** (in Traditional Chinese, 「工作坊」 is now 「群組」), including in the trash's section headings and the location shown under notes.
- The sidebar's **Groups** tab lists groups by your role in them: groups where you hold the built-in **Admin** role first, then those where you hold the built-in **Member** role, then those where you have a custom role, each by name. Before, all groups were listed by name, so groups you created could end up below ones others added you to. `GET /api/groups` returns them in the same order, and so do **Settings → Groups**, the group lists in **Move to…** and **Copy to…**, and **Move to** and **Copy to** in the sidebar's selection mode.
- The group menu's items have icons.
- Dragging a link to a note on this site into a note — a note from the sidebar, or a link from another tab — now makes a link to that note, as pasting it does (#352).
- The main buttons and the email, password and other text fields on the sign-in, create-account, reset-password, link-account and app-authorization pages, and on the change-password page you're sent to when a password change is required, are taller (44 pixels instead of 32) and the button text is larger (16 px instead of 14 px), so they are easier to hit; this includes each **Sign in with …** button. Other pages, including the change-password form in Settings, keep the 32-pixel controls.
- The in-app AI now gets the selected blocks as the same Markdown that MCP and the API read, so colors, side-by-side columns, image widths and table column widths go to the model with them. For every AI action, built-in or custom, the server puts a fixed instruction at the start of the action's system prompt asking the model to keep that markup; admins can't change or remove it. The result is checked before it is shown, with the same column, size and color checks as a write over MCP: one that writes columns or sizes in any other form isn't applied, and the AI box shows "The AI edit failed; the note was not changed."; one with a color outside the editor's ten names isn't applied either. See [AI](../ai.md).
- MCP's `list_trash` pages through the whole trash with `cursor` and `nextCursor` instead of returning only the 100 notes most recently moved there, and `truncated` now means that more notes follow. Each entry carries `folderPath`, where `restore_note` usually puts the note back. `list_notes` and `list_trash` can return fewer notes than a full page when the notes are large, with `pageCutShort: true`; keep paging until `nextCursor` is `null`.
- `GET /api/trash` and MCP's `list_trash` order notes moved to the trash in the same millisecond by id, descending.
- MCP's `create_note` answers `server_busy`, having created nothing, when it runs into a lock or serialization conflict; it used to answer `internal`.
- The instructions an MCP client gets when it connects say that `list_folders` shows the folders notes sit in, and no longer give the outline's 100-section limit.

### Fixed

- The **Restore** icon in **Trash** is now a full counter-clockwise arrow; at small sizes it used to look like a plain circle.
- Rewriting part of a note over MCP (`edit_note`), the REST API (`POST /api/notes/:id/edits`) or with the in-app AI no longer resets the widths of the images and table columns in it: they now read as HTML that carries the widths, and writing that back unchanged keeps them. See [Sizes](../ai-editing.md#sizes) (#305).
- Rewriting a section that holds side-by-side columns over MCP (`edit_note`) or the REST API (`POST /api/notes/:id/edits`), sending back what was read, no longer turns the row into ordinary blocks: rows now read with their column tags, and writing that back unchanged keeps the row. See [AI editing](../ai-editing.md#columns).
- Writing over MCP, the REST API or with the in-app AI now saves an image, or another media block, whose address is a full address of one of this site's uploads (`https://<your site>/api/uploads/<id>`) with the relative address `/api/uploads/<id>`. An image inside a toggle heading or a toggle list item, written as HTML, used to be saved with the full address, and copying the note then didn't give the copy its own copy of that image. An image already saved that way keeps its full address until it is written again.
- The in-app AI no longer turns a diagram in the blocks it rewrites into a code block: a ```` ```mermaid ```` fence in its result becomes a [diagram](../diagrams.md) again, as it does over MCP.
- Markdown the editor fails to parse, such as `<div data-content-type="paragraph">`, is now refused with `400 unsupported_block` over the REST API (the tool error `unsupported_block` over MCP) instead of a server error; in the in-app AI, such a result shows an error instead of leaving the AI box in its streaming state.
- On narrow windows, a message that pops up while the sidebar drawer is open (for example **Moved to the trash** with its **Undo** button, after you delete another note from the drawer) can now be reached with the keyboard and by screen readers. Before, it could be seen and clicked, and screen readers announced it, but they couldn't move to it or its buttons and the keyboard couldn't reach them.
